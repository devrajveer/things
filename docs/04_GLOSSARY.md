# Glossary — Single Source of Truth

This document defines every term, ID format, enum value, and status used in the platform. **Every other document and every piece of code must conform to this.** If you need a new term, add it here first.

> Codename for the platform: **`yourplatform`** — replace with the chosen brand name in all code and docs after naming is finalized. The Implementation Playbook contains the rename procedure.

## 1. Domain Entities

| Entity | Definition | ID prefix |
|---|---|---|
| **User** | A human account that can log in. | `usr_` |
| **Organization** | A billing + ownership container. Holds users via memberships. Has a tier (subscription plan). | `org_` |
| **Project** | A logical isolation boundary for devices, dashboards, rules. All telemetry belongs to one project. Multi-tenancy boundary. | `prj_` |
| **Membership** | Junction record linking a user to an organization or project, carrying a role. | `mem_` |
| **Device** | A physical or virtual thing that produces telemetry. Belongs to exactly one project. | `dev_` |
| **DeviceProfile** | A reusable template defining a device's payload schema, codec, region, and protocol settings. | `dpf_` |
| **Stream** | A unique time-series identified by `(device_id, key)`. Auto-discovered from incoming telemetry. | `str_` |
| **Datapoint** | A single value at a single timestamp on a single stream. Not addressable by ID — addressed by `(stream_id, time)`. | (none) |
| **Dashboard** | A grid layout of widgets visualising one or more streams. | `dsh_` |
| **Widget** | A single visual element on a dashboard (chart, gauge, table, etc.). | `wid_` |
| **Rule** | A declarative trigger + action specification. Evaluated against incoming telemetry. | `rul_` |
| **Alert** | An instance of a rule firing. Carries a payload and delivery state. | `alt_` |
| **AlertDelivery** | An attempt to send one alert through one channel. | `dlv_` |
| **APIKey** | A scoped, revocable credential for HTTP API access. | `key_` |
| **DeviceCredential** | A per-device secret used for MQTT/HTTP ingestion auth. | `dcr_` |
| **DeviceDownlink** | A queued message to be sent to a device on its next available window. | `dwn_` |
| **AIConversation** | A persisted multi-turn LLM chat session. | `cnv_` |
| **AIMessage** | A single message within a conversation. | `msg_` |
| **AIProposal** | A structured artifact (dashboard, rule) generated by an agent, awaiting human confirmation. | `prp_` |
| **AuditEvent** | An immutable record of a state-changing action. | `aud_` |
| **Subscription** | A billing subscription on an organization. | `sub_` |
| **Webhook** | A user-configured outbound URL receiving event notifications. | `whk_` |
| **Token** (auth) | Short-lived JWT for session auth. Not persisted. | (jwt) |
| **RefreshToken** | Long-lived rotating refresh credential. | `ref_` |

## 2. ID Format Specification

All IDs except LoRaWAN identifiers follow this format:

```
<prefix>_<base32_crockford_22_chars>
```

- Underlying value is a ULID (128 bits).
- Encoded in Crockford base32 (case-insensitive, no ambiguous chars).
- Length excluding prefix and underscore: **26 characters** (standard ULID length).
- Lexicographically sortable by creation time.

**Examples:**
```
prj_01H8XGMC5BJ3K7Y2A6D9F4P3QN
dev_01H8XGN8R3M2W7Z1B5K8C2N6X4
str_01H8XGNYHK2P3Q4R5S6T7U8V9W
```

**Generation:** `python-ulid` for Python, `ulid` package for Node, server-generated only. **Clients never generate IDs.**

**Validation regex:** `^[a-z]{3}_[0-9A-HJKMNP-TV-Z]{26}$`

```

```

```

```

### `DeviceStatus`
```
provisioned | active | inactive | disabled | deleted
```
- `provisioned`: created, no data received yet
- `active`: data received within the last 24h
- `inactive`: no data within last 24h, but not disabled
- `disabled`: manually disabled, ingestion rejected
- `deleted`: soft-deleted; data retained per retention policy

## 4. Reserved Naming Conventions

### Service names (used in container names, log fields, tracing)
```
api | ingest | realtime | worker | ai-worker | scheduler | web | edge-agent | mqtt-broker | nats | postgres | redis | minio | chirpstack | caddy
```

### NATS subjects
Format: `<category>.<resource>.<version>.<project_id>[.<specifier>]`

Categories:
```
ingest | telemetry | alerts | rules | ai | audit | devices | system
```

Examples:
```
ingest.raw.v1.prj_01H8XGMC5BJ3K7Y2A6D9F4P3QN
telemetry.datapoint.v1.prj_01H8XGMC5BJ3K7Y2A6D9F4P3QN
alerts.fired.v1.prj_01H8XGMC5BJ3K7Y2A6D9F4P3QN
devices.state.v1.prj_01H8XGMC5BJ3K7Y2A6D9F4P3QN.dev_01H8XGN8R3M2W7Z1B5K8C2N6X4
audit.event.v1.prj_01H8XGMC5BJ3K7Y2A6D9F4P3QN
```

### MQTT topics (device-facing)
Format: `v1/<project_id>/<device_id>/<channel>`

Channels:
```
up        device → cloud  telemetry payload
down      cloud → device  command/downlink
state     device → cloud  retained current state
event     device → cloud  discrete event
ack       device → cloud  acknowledgement of downlink
```

Example:
```
v1/prj_01H8XGMC5BJ3K7Y2A6D9F4P3QN/dev_01H8XGN8R3M2W7Z1B5K8C2N6X4/up
```

### HTTP API URL prefix
```
https://api.<domain>/v1/...
```

### Database table names
- snake_case, plural, no schema prefix in v1
- e.g. `users`, `organizations`, `devices`, `device_profiles`, `audit_events`

### Database column names
- snake_case
- IDs always end with `_id` (e.g., `project_id`)
- Booleans always start with `is_` or `has_` (e.g., `is_enabled`)
- Timestamps always end with `_at` (e.g., `created_at`, `last_seen_at`)
- Counts always end with `_count` (e.g., `device_count`)
- All `*_at` columns are `TIMESTAMPTZ` (UTC)

### Code identifiers
| Language | Style |
|---|---|
| Python module/file | `snake_case.py` |
| Python class | `PascalCase` |
| Python function/var | `snake_case` |
| Python constant | `UPPER_SNAKE_CASE` |
| TypeScript file | `kebab-case.ts` (no `index.ts` outside of barrels) |
| TypeScript class/interface | `PascalCase` |
| TypeScript function/var | `camelCase` |
| TypeScript constant | `UPPER_SNAKE_CASE` |
| TypeScript type | `PascalCase` |
| React component file | `PascalCase.tsx` |
| Go file | `snake_case.go` |
| Go exported | `PascalCase` |
| Go unexported | `camelCase` |
| Arduino class | `PascalCase` |
| Arduino method | `camelCase` |

## 5. Versioning Conventions

| Subject | Versioning scheme |
|---|---|
| HTTP API | URL path: `/v1`, `/v2`. Major version only. |
| NATS event schemas | In subject: `.v1`, `.v2`. Per-event versioning. |
| SDKs | SemVer 2.0 (`major.minor.patch`). Major bump for breaking changes. |
| Platform release | CalVer: `YYYY.MM.PATCH` (e.g., `2025.04.0`). |
| Database migrations | Alembic timestamped: `YYYYMMDDHHMM_short_description.py` |
| Docker images | Tagged with: git SHA (immutable), branch name (mutable), CalVer release tag |

## 8. Time, Units, and Numeric Conventions

- **All timestamps**: ISO-8601 with timezone, UTC, milliseconds precision: `2025-01-15T10:30:00.123Z`
- **Internal storage**: `TIMESTAMPTZ` in Postgres
- **Wire format**: ISO-8601 string in JSON, never Unix epoch
- **Durations**: ISO-8601 duration strings in API (`PT5M`, `PT1H30M`) or seconds as integer in events (`window_s`)
- **Numeric values**: `double precision` (float64). No integer-typed measurements.
- **Currency**: ISO-4217 code + minor units integer. `{"amount":1999,"currency":"USD"}` = $19.99
- **Booleans**: literal `true` / `false`. Never 0/1, never "yes"/"no" strings.
- **Geographic coordinates**: `{"lat": 40.7128, "lng": -74.0060}`. Never arrays. Always WGS84.
- **Measurements**: SI units in canonical streams. Display unit conversion happens in the frontend.
- **Floating-point comparison**: never `==`. Use absolute or relative epsilon based on context.

## 10. Status / Lifecycle State Machines

### Device lifecycle
```
provisioned ──first_data──▶ active ──24h_silent──▶ inactive
       │                       │                       │
       └────disable────────────┴────disable───────────┘
                               │
                              disabled ──enable──▶ active
                               │
                              delete (soft)
                               │
                              deleted
```

### Alert lifecycle
```
(rule fires) ──▶ firing ──ack──▶ acknowledged ──resolve──▶ resolved
                  │                    │
                  ├──snooze────────────┤
                  ▼                    ▼
                 snoozed ──expire──▶ firing
```

### AI proposal lifecycle
```
proposed ──apply──▶ applied
   │
   ├──reject──▶ rejected
   │
   └──30min_no_action──▶ expired
```
